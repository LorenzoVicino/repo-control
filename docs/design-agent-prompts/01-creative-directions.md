# Prompt — Esplorazione di tre direzioni creative

## Prompt pronto da incollare

Partendo dal master brief di repo-control, genera **tre direzioni di product design realmente divergenti**. Non produrre tre variazioni cromatiche dello stesso dashboard layout.

### Direzione A — Precision Workbench

Esplora un workbench tecnico ad alta precisione: superfici graphite o ink, contrasto controllato, griglie rigorose, indicatori di stato compatti, tipografia netta e un uso misurato di cyan/green/amber. Deve evocare strumenti professionali e IDE moderni, non un terminale cyberpunk.

### Direzione B — Paper & Signal

Esplora un'interfaccia editoriale chiara, basata su warm white, ink quasi nero, cobalt e safety orange. Usa spazio, regole tipografiche, sezioni e dati in linea più delle card. Deve sembrare un quaderno operativo di altissima qualità, non un gestionale beige.

### Direzione C — Modular Control Plane

Esplora un sistema adattivo a pannelli agganciabili, con superfici neutre stratificate e un colore di contesto per workspace/repository. Deve rendere visibili persistenza, split view e cambio di contesto, senza imitare letteralmente VS Code o un window manager.

Puoi rinominare le tre direzioni se trovi metafore migliori, ma mantieni la divergenza strutturale.

### Schermate campione obbligatorie

Per ciascuna direzione mostra le stesse quattro schermate, con gli stessi dati realistici:

1. Dashboard workspace con repository sani, dirty, behind e attività recente.
2. Repository / Modifiche con lista file, diff selezionato e commit composer.
3. Automazioni con canvas, libreria nodi, inspector e run attivo.
4. Agent sessions con ricerca, provider status, risultati e dettaglio sessione.

### Per ogni direzione consegna

- una frase manifesto e 5 principi;
- moodboard descritta con riferimenti a qualità, non copie di prodotti;
- anatomia della shell e del sistema di navigazione;
- palette con valori colore e ruoli semantici;
- coppia tipografica e scala;
- superficie, bordo, radius, shadow e density strategy;
- stile di status, command, path, branch, diff, log e graph node;
- un frame desktop `1440 × 960` per ciascuna schermata campione;
- un estratto laptop e uno mobile che provino la capacità responsive;
- rischi e trade-off;
- stima di compatibilità con React + Material UI: alta, media o bassa, motivata.

### Confronto finale obbligatorio

Chiudi con una matrice che assegni un punteggio da 1 a 5 a:

- identità e memorabilità;
- velocità di scansione;
- densità sostenibile;
- leggibilità di Git/Docker/log;
- chiarezza delle azioni rischiose;
- adattabilità tra dashboard, canvas e terminale;
- accessibilità;
- costo di implementazione.

Raccomanda una direzione o un ibrido preciso. Se proponi un ibrido, specifica quali elementi provengono da ogni direzione; non usare “prendiamo il meglio di tutte” come risposta generica.
